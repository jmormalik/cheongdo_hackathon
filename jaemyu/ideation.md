# 아이디어: 이번 주 농사

## 제품 요약

**청도 초보 농부가 지원 작물과 생육 단계를 선택하면, 출처와 기준일이 확인된 재배 자료와 지역 날씨를 바탕으로 이번 주 점검할 일을 한 화면에 정리해 주는 모바일 우선 웹 앱.**

한 번에 농업 정보를 모두 제공하는 종합 플랫폼이 아니라, 초보 농부의 반복 질문인 **“이번 주에 무엇을 확인하고 준비해야 하지?”**에 집중한다.

핵심 차별점은 단순히 AI 답변을 제공하는 것이 아니라, 점검 항목마다 근거 자료와 기준일을 함께 보여주고 근거가 부족하면 추천을 보류하는 것이다.

## 문제와 사용자

### 해결할 문제

초보 농부는 작물 관리 시기와 날씨 정보를 여러 곳에서 찾아 직접 비교해야 한다. 자료를 찾았더라도 현재 생육 단계에 맞는 내용인지, 얼마나 최신인지, 어디까지 믿어도 되는지 판단하기 어렵다. 그 결과 필요한 작업을 놓치거나 확인에 시간을 쓸 수 있다.

### 우선 사용자

- 청도에서 소규모 농사를 시작한 지 얼마 되지 않은 농부
- 여러 정보원을 오가며 재배 시기와 이번 주 작업을 확인하는 사용자
- 계정 생성 없이 휴대전화에서 간단한 안내를 확인하고 싶은 사용자

### 작물 범위 결정 원칙

첫 버전은 **작물 한 종만** 지원한다. 특정 작물을 청도의 대표 작물이라고 미리 단정하지 않는다. 공개 재배 자료의 신뢰성, 날씨·지역 데이터 이용 가능성, 해커톤 안에 검증 가능한지를 확인한 뒤 작물을 선정하고 PRD에 근거와 함께 기록한다. 자료 검증 전에 작물별 조언을 사실처럼 작성하지 않는다.

작물 후보는 팀이 실제로 확인한 공식·공공 재배 자료로만 비교한다. 후보별 출처, 지원하는 생육 단계, 갱신일, 이용 조건을 기록하고, 자료가 가장 명확하고 MVP에서 재현 가능한 한 종을 선택한다. 후보와 근거를 확인하기 전에는 작물명을 확정하거나 “청도 대표 작물”이라고 홍보하지 않는다.

## “이번 주”와 데이터 갱신 정의

- 기간은 **한국 시각(Asia/Seoul) 기준 이번 주 월요일 00:00부터 일요일 23:59까지**로 한다.
- 화면 상단에 실제 날짜 범위를 함께 표시한다. 주간 범위는 사용자가 화면을 연 시점을 기준으로 계산한다.
- 사용자가 화면을 열거나 새로고침할 때 필요한 데이터와 점검 결과를 다시 조회한다. 백그라운드 시간별 갱신은 MVP에 넣지 않는다.
- 각 자료에는 원천의 기준일/갱신 시각과 앱 조회 시각을 구분해 표시한다.
- 원천 자료가 정한 유효 기간을 확인할 수 없거나 자료가 오래된 것으로 판단되면 최신 정보로 취급하지 않고 경고하거나 해당 추천에서 제외한다.

## 핵심 가치

작물과 생육 단계에 맞는 주간 점검 항목을 한 화면에 모으고, 각 항목에 **왜 필요한지, 어떤 자료를 근거로 했는지, 자료가 언제 기준인지**를 표시한다. 시간 절감 효과를 아직 측정하지 않았으므로 절감률이나 수익 증가를 주장하지 않는다.

## 핵심 사용자 흐름

1. 사용자가 데모 화면에서 지원 작물 한 종과 생육 단계를 선택한다.
2. 앱이 확인 가능한 지역 날씨와 작물 재배 자료를 조회한다.
3. 이번 주 날짜 범위를 표시하고, 근거가 확인된 점검 항목만 우선순위가 있는 카드로 보여준다.
4. 사용자는 카드에서 추천 이유, 자료 출처, 기준일을 확인한다.
5. 사용자가 추가 질문을 하면 에이전트가 필요한 자료를 조회해 답하고, 근거가 부족하면 부족한 점과 확인 방법을 알린다.

## MVP 범위

### 해커톤 당일 반드시 완성할 기능

- 계정 없이 시작할 수 있는 반응형 웹 데모
- 지원 작물 한 종과 생육 단계 선택
- 확인된 재배 자료와 이용 가능한 지역 날씨를 이용한 주간 점검 목록
- 점검 항목별 근거, 출처, 기준일 표시
- 사용자의 농작업 질문을 처리하는 실제 Copilot SDK 및 Microsoft Agent Framework 연동
- 데이터 누락·조회 실패·오래된 자료를 성공 결과처럼 꾸미지 않는 안내

### MVP에서 제외

- 농산물 가격 예측 및 수익 극대화 주장
- 지원사업 자격 판정 및 공고 크롤링
- 병해충 자동 진단, 사진 진단, 방제 처방
- 다작물 지원, 농장별 장기 기록, 계정, 알림 발송, 결제

이 항목들은 핵심 사용자 흐름이 동작하고 데이터 출처와 이용 조건을 검증한 뒤 별도 범위로 검토한다. 해커톤 시연을 위해 신뢰할 수 없는 값이나 출처 없는 조언을 실제 데이터처럼 제시하지 않는다.

## 화면과 결과 카드

주요 화면은 **작물·생육 단계 선택**, **이번 주 점검 목록**, **근거를 확인하는 질문/답변 영역**으로 제한한다. 각 작업 카드는 다음 정보를 제공한다.

- 작업 또는 점검 항목
- 권장 이유와 해당 생육 단계
- 참고 자료의 제목·출처 링크
- 자료 기준일 또는 조회 시각
- 적용 범위와 주의사항

자료를 확인할 수 없는 항목은 추천 카드로 만들지 않는다. 필요한 정보가 부족하면 먼저 사용자에게 작물이나 생육 단계를 확인한다.

### 필수 화면 상태

- **입력 화면:** 지원 작물과 생육 단계 선택. 목록에서 고르도록 하며 임의 입력이나 미지원 작물 요청은 명시적으로 처리한다.
- **주간 안내:** 날짜 범위, 데이터 상태, 점검 카드 목록을 한눈에 보여준다.
- **근거 상세:** 카드의 출처 원문, 기준일, 적용 범위와 주의사항을 보여준다.
- **질문/답변:** 안내 목록과 연결된 질문 입력 및 답변, 답변의 출처를 제공한다.
- **로딩:** 조회 중임을 알리고 반복 제출을 방지한다.
- **빈 결과:** 유효한 자료에서 해당 기간의 점검 항목을 찾지 못했음을 설명한다. 빈 목록을 AI가 임의로 채우지 않는다.
- **부분 장애:** 날씨 조회가 실패했지만 재배 자료는 있으면 재배 자료 기반 안내만 보여주고 날씨 반영이 안 됐음을 표시한다.
- **오류:** 필수 자료 조회가 모두 실패하거나 입력이 잘못되면 가능한 다음 조치를 설명하고, 성공한 것처럼 결과를 보여주지 않는다.

## AI 에이전트 활용

AI는 근거 자료를 찾고 이해하기 쉬운 설명으로 정리하는 역할을 맡는다. 재배 사실이나 농작업 처방을 근거 없이 만들어내지 않는다.

1. **요청 확인:** 작물, 생육 단계, 지역 등 필요한 입력이 있는지 확인한다.
2. **입력 검증:** 지원하지 않는 작물·생육 단계이거나 필수 값이 없으면 지원 범위와 필요한 입력을 안내한다.
3. **도구 오케스트레이션:** Microsoft Agent Framework가 주간 점검 질문에 재배 자료 조회와 날씨 조회를 사용한다. 날씨가 없을 때는 날씨 조건을 반영한 추천을 만들지 않는다.
4. **근거 수집:** 각 도구는 결과와 함께 출처, 원천 기준일/갱신 시각, 앱 조회 시각, 성공·부분 성공·실패 상태를 반환한다.
5. **답변 생성:** 서버에서 GitHub Copilot SDK를 통해 모델에 요청하고, 조회 결과에 근거한 설명을 만든다.
6. **검증·표시:** 서버가 응답 구조와 출처 참조를 검증한다. 근거가 없는 구체적 조언은 제외한다. 정보가 부족하거나 오래된 경우 이를 명확히 표시한다.

### 도구 계약 초안

세부 언어별 타입과 실제 API는 TRD에서 확정한다. 아래 계약은 필요한 의미를 고정하기 위한 초안이다.

| 도구 | 입력 | 결과 |
|---|---|---|
| `GetCropGuidance` | 지원 작물 ID, 생육 단계 ID, 지역 ID, 주간 날짜 범위 | 점검 항목 목록. 항목마다 제목, 이유, 적용 단계, 출처 URL/제목, 원천 기준일, 적용 범위 포함 |
| `GetLocalWeather` | 지역 ID, 시작일, 종료일 | 날짜별 예보, 출처, 원천 갱신 시각, 단위, 조회 상태 |

도구 결과에는 반드시 `status`(성공/부분 성공/실패)와 사용자에게 표시 가능한 오류 종류를 포함한다. 모델은 도구 결과에 없는 출처나 날짜를 만들어서는 안 된다.

### 응답 구조 초안

프론트엔드가 모델의 임의 서식에 의존하지 않도록 서버는 검증 가능한 구조화 결과를 반환한다. 최소 필드는 다음과 같다.

- `summary`: 주간 요약
- `dateRange`: 표시할 시작일과 종료일
- `tasks`: 제목, 이유, 주의사항, 근거 참조 ID를 가진 점검 항목 목록
- `sources`: 제목, URL, 원천 기준일, 앱 조회 시각
- `dataStatus`: 사용한 자료의 성공·부분 성공·실패 상태와 표시할 설명

구조 검증에 실패하거나 근거 참조가 없는 항목은 UI에 추천으로 표시하지 않는다. 상세한 스키마, 재시도 여부와 제한 시간은 실제 SDK 동작을 확인한 뒤 TRD에 정한다.

Copilot SDK와 Agent Framework는 개발 보조용으로만 언급하지 않고, 위의 앱 실행 흐름에서 실제로 사용한다. 구현 언어와 SDK 간 호환성, 배포 환경에서의 실행 조건은 코드를 본격적으로 작성하기 전에 공식 문서와 최소 동작 예제로 확인한다. 기술 연동이 확인되지 않으면 기능을 허위로 완성된 것처럼 설명하지 않는다.

## 데이터·신뢰 원칙

- 공식 또는 이용 조건이 확인된 자료를 우선 사용하고, 자료명·URL·기준일·확인일을 기록한다.
- 외부 데이터 원문은 신뢰되지 않은 입력으로 취급한다. 데이터 안에 포함된 지시문이 에이전트의 동작이나 규칙을 바꾸지 않도록 한다.
- 조회 실패, 빈 응답, 오래된 자료를 최신 정보인 것처럼 표시하지 않는다.
- AI 설명과 원문 근거를 구분하고, 사용자가 원문을 직접 확인할 수 있게 한다.
- 일반적인 재배 안내를 개별 농장에 대한 확정 처방, 병해충 진단 또는 수확량 보장으로 표현하지 않는다.
- 농장 상세 정보나 개인정보를 꼭 필요한 범위 이상 수집하지 않는다.
- 비밀 키는 서버 측에서만 사용하며 공개 저장소나 브라우저 코드에 포함하지 않는다.

## 구현 가능성 확인 게이트

작물과 기능을 확정하기 전에 아래 항목을 확인한다. 확인되지 않은 데이터 기능은 MVP의 약속으로 포함하지 않는다. 담당자는 팀에서 지정하고, 해커톤 당일 첫 제출 및 최종 제출 시각을 기준으로 게이트를 확인한다.

| 확인 대상 | 통과 기준 | 실패 시 처리 |
|---|---|---|
| 작물 재배 자료 | 선택 작물의 단계별 안내 자료, 출처, 기준일과 이용 조건을 기록 | 출처 확인이 안 된 작업 안내는 제외. 테스트 fixture는 데모 자료임을 명확히 표시 |
| 지역 날씨 | 청도 지역에 사용할 데이터 출처, 갱신 기준과 이용 조건을 확인 | 날씨 반영 기능을 비활성화하고, 날씨를 반영하지 않은 자료만 구분 표시 |
| Copilot SDK | 선택한 언어·서버 환경에서 앱의 모델 요청과 오류 처리가 동작 | 필수 기술을 다른 모델 API로 대체하지 않는다. SDK 연동이 안 되면 해당 기능을 완료했다고 주장하지 않고 해결 우선 |
| Agent Framework | 에이전트가 등록된 도구를 실제 호출하고 결과를 전달하는 최소 예제를 확인 | 단순 순차 호출로 대체해 필수 기술을 충족했다고 주장하지 않는다. 구현 범위를 줄여 Framework 흐름을 검증 |
| Azure 배포 | 허용된 Azure 기본 도메인에서 심사자가 로그인 없이 핵심 흐름을 이용 | 배포를 완료할 때까지 공개 제출 준비로 간주하지 않는다 |

필수 기술의 실제 연동이 확인되지 않았다면 이를 숨기거나 일반 모델 호출만으로 대체했다고 주장하지 않는다. 팀은 해당 기술 요구사항을 충족할 수 있는 접근을 다시 정하고 구현 범위를 조정한다.

### 당일 실행 순서와 담당 배정

현재 역할별 담당자는 정해져 있지 않으므로 문서에서 임의로 이름을 지정하지 않는다. 팀은 바로 담당자를 배정하고, 다음 게이트를 순서대로 확인한다.

1. **첫 제출 전(15:00 KST):** 작물 자료/날씨 출처와 이용 조건을 확인하고, Copilot SDK 및 Agent Framework의 최소 동작을 검증한다. 하나라도 불가능하면 해당 데이터 기능을 축소하고 원인을 기록한다.
2. **최종 제출 전(16:30 KST):** 공개 Azure 기본 도메인에서 로그인 없이 핵심 흐름을 재시연하고, 문서·출처·오류 상태를 점검한다.
3. 운영 일정이 변경되면 최신 현장 공지를 우선하며, 담당자와 완료 상태를 팀 내부 작업표에 기록한다.

실시간 데이터 서비스가 일시적으로 실패할 때만 사전에 검증한 fixture를 개발·반복 테스트에 사용할 수 있다. 사용자에게 노출할 경우 **“데모 예시 데이터—실시간 정보 아님”**을 눈에 띄게 표시하고 실제 예보나 최신 안내처럼 표현하지 않는다.

필수 Copilot SDK와 Microsoft Agent Framework를 우회해 다른 API나 직접 호출로 바꾸는 것은 대안으로 삼지 않는다. 해커톤 평가에서 두 기술은 필수이므로, 데이터 범위와 부가 기능을 줄이더라도 실제 앱 흐름에서 해당 기술을 사용해야 한다.

## 오류 및 예외 처리 기준

- **미지원 작물/생육 단계:** 지원 목록을 안내하고, 추측성 안내를 만들지 않는다.
- **필수 입력 누락:** 결과를 생성하기 전에 누락된 항목만 질문한다.
- **날씨 자료 실패:** 날씨를 반영하지 않은 재배 자료 안내만 제공하고, 날씨 확인 실패를 표시한다.
- **재배 자료 실패:** 해당 작업 추천을 표시하지 않고 원문 확인 또는 재시도를 안내한다.
- **오래되었거나 기준일이 없는 자료:** 원천의 갱신·유효성 기준에 따라 오래된 자료임을 표시하거나 추천에서 제외한다. 모든 데이터에 임의의 공통 만료 시간을 적용하지 않는다.
- **도구/모델 오류 또는 시간 초과:** 결과를 성공처럼 반환하지 않고 재시도 안내와 상태를 표시한다. 구체적인 제한 시간은 선택한 SDK와 공급자 제약을 확인해 TRD에 기록한다.
- **모순된 자료:** 출처와 적용 범위를 비교할 수 없으면 임의로 하나를 선택하지 않고 충돌을 표시하며 전문가 또는 원문 확인을 권한다.
- **결과 없음:** 해당 조건에서 확인된 항목이 없다고 설명하고, 출처 없는 대체 작업을 생성하지 않는다.

## 데모 완료 기준

- 심사자가 로그인이나 별도 자격 증명 없이 앱을 열 수 있다.
- 지원 작물과 생육 단계를 선택해 주간 점검 결과를 볼 수 있다.
- 모든 표시된 점검 항목에서 이유와 출처를 확인할 수 있다.
- 질문에 대한 답변이 실제 에이전트 도구 흐름을 사용하며, 자료가 없을 때는 그 사실을 알린다.
- 데이터 조회 실패와 잘못된 입력을 사용자에게 이해 가능한 상태로 보여준다.
- 핵심 흐름을 처음부터 끝까지 반복 시연할 수 있다.
- 점검 결과는 이번 주 날짜 범위를 표시하며, 화면을 열거나 사용자가 갱신할 때 최신 조회 상태를 확인한다.
- 모든 표시된 점검 항목은 검증 가능한 출처 참조를 가지며, 데이터 상태에 따라 안내가 달라진다.

## 효과 측정 계획

시간 절감이나 생산성 향상은 아직 검증되지 않았으므로 수치로 주장하지 않는다. 사용자 테스트를 할 수 있으면 같은 과업을 다음 두 방식으로 수행하도록 하고 실제 결과만 기록한다.

1. 앱 없이 재배 자료와 날씨 정보를 직접 찾아 이번 주 점검 항목을 정한다.
2. 앱에서 같은 작물·생육 단계로 점검 항목을 확인한다.
3. 각 방식의 완료 시간, 출처를 찾았는지, 사용자가 안내를 이해했는지를 기록한다.

표본과 측정 결과가 부족하면 정량적인 성과를 주장하지 않고, MVP에서 검증하려는 가설로만 PRD에 남긴다. 기능 검증 기준은 별도로 유지한다: 결과가 있는 모든 점검 카드에 근거가 연결되고, 데이터 실패 시 상태가 명시되어야 한다.

## 배포 및 제출 고려사항

- Azure에 배포하고 `*.azurewebsites.net`, `*.azurecontainerapps.io`, `*.azurestaticapps.net` 등 허용된 Azure 기본 도메인을 사용한다. 커스텀 도메인은 사용하지 않는다.
- 불필요한 Azure 서비스를 추가하지 않고, 필요한 최소 구성으로 배포한다.
- 공개 데모에서 핵심 기능을 로그인 없이 사용할 수 있게 한다.
- 결과 제출을 위해 공개 저장소 루트에 `PRD.md`와 `TRD.md`를 준비하고, 배포 URL과 심사 대상 커밋을 확인한다.
- 제출 이슈에 비밀번호, 토큰 등 자격 증명을 입력하지 않는다.
- 제출 마감은 **2026년 11월 5일 16:30 KST**이며, 행사 당일 공개 주제와 운영진 안내를 우선한다.
